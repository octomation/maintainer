# The hub frontend

The Preact + TypeScript + Vite application that `maintainer service run`
serves at `/status`, `/inbox` and `/tablo`. The built `dist/` is committed and
embedded with `go:embed` (`assets.go`), so the Go module builds without Node;
`make web-check` keeps `dist/` in step with the sources.

## What is where

```text
assets.go              package web: //go:embed dist, Dist() for the service
index.html             the document; Vite rewrites the script tag at build time
vite.config.ts         Vite, the dev proxy to the service, vitest
src/main.tsx           applies the stored theme, mounts <App/> into #app, loads the styles
src/app.tsx            the shell: Sidebar, theme, the page of location.pathname
src/theme.ts           dark (default) | light | system, remembered in localStorage
src/api/types.ts       the TypeScript types of every /api/v0 answer
src/api/client.ts      ApiClient: the requests, the headers, ApiError
src/api/mock.ts        mockApi(): a fetch over the fixtures for component tests
src/api/fixtures/      JSON answers of the Go handler for its fixture mirror
src/lib/query.ts       TaskQuery <-> URL search (queryFromSearch, pushQuery keeps task, group, layout; replaceSearch tells the shell)
src/lib/media.ts       the breakpoints (900, 600) and useMediaQuery
src/lib/task.ts        ?task=<id>: the full issue page in the URL (openTask, closeTask, useOpenTask)
src/components/        Sidebar (+ RepositoryTree), CommandBar, TopBar (+ ViewSwitch), TaskFilters, Display,
                       Popover, TaskDetails, IssuePage, Drawer (the peek panel), Glyphs,
                       Chip, Icon, States
src/styles/            tokens.css (every token of DESIGN.md, both themes), fonts.css
                       (Inter), base.css (the shell and the shared components)
DESIGN.md              the design guidelines: tokens, layout, components, states
src/pages/props.ts     PageProps: what the shell hands a page
src/pages/status/      /status, MAIN-156
src/pages/inbox/       /inbox, MAIN-157 (grouping.tsx: the groups of View → Grouping)
src/pages/tablo/       /tablo, MAIN-158
src/test/setup.ts      testing-library cleanup
dist/                  the committed build, the Inter files included
```

## Commands

```sh
npm ci              # the exact dependencies of package-lock.json
npm run check       # tsc --noEmit
npm test            # vitest, once
npm run test:watch  # vitest in watch mode
npm run dev         # Vite on http://localhost:5173 against a running service
npm run build       # rewrites dist/; commit the result
make web-check      # from the repository root: all of the above and a diff with dist/
```

`npm run dev` proxies `/api` to `http://maintainer.localhost:17841` and
rewrites `Host` and `Origin` to that address, which the service requires;
set `MAINTAINER_SERVICE` to proxy another address, such as a service started
with `--listen 127.0.0.1:0`. Start the service first:
`maintainer service run`.

## The contract with the service

- The Go types are the source of truth. The fixtures under `src/api/fixtures/`
  are generated by `go test ./internal/service/web -run TestFrontendFixtures -update`
  and checked without the flag: a fixture must decode into the Go types with
  no unknown field and encode back to the same document. Change a type on
  the Go side first, regenerate the fixtures, then update `types.ts`.
- `ApiClient` keeps the `ETag` of a task detail and sends it as `If-Match`
  on `triage`; a `412` or `409` arrives as an `ApiError` with that status.
- Before the first index, list and catalog answers are `202` with
  `data: null` and `refreshing: true`; the pages show `<Indexing/>` and
  poll. `GET /api/v0/checkouts` does the same before the first collection.
- Every mutation carries `X-Requested-With: maintainer`; the browser adds
  `Origin`. There is no CORS: the application is served by the service.

## Adding a page

A page lives in `src/pages/<page>/index.tsx` and exports a component that
takes `PageProps` (`client` and `onStatus`). The three routes are registered
in `src/components/Sidebar.tsx` (`ROUTES`) and rendered in `src/app.tsx`; the
service serves the document at those paths only, so a new path also needs a
route in `internal/service/web/handler.go` (`Pages`).

What a page gets from the shell:

- `TopBar` with the `title`, the filters as children and the `actions` on the
  right (the list/board switch and Display only); on a narrow screen it shows
  the menu button that opens the sidebar and wraps the chips into a second
  row. `ViewSwitch` links the list (`/inbox`) and the board (`/tablo`) with
  the current filters. Search is the command bar of the shell (`CommandBar`,
  opened from the sidebar, `/` or Ctrl/Cmd+K), which opens an issue as the
  full page on the inbox or the board.
- `TaskFilters` with `value`, `facets`, `onChange`, an optional `catalog` for
  milestone titles, `showState`, `defaultState` and `showColumn`: the dashed
  Filter button (or the F key) opens a 210 px menu of dimensions in groups
  (State, Status, Content; Priority, Estimate, Labels, Type; Milestone,
  Repository, Owner, Assignee) and each dimension its values with the counts
  of the facets; Content is the text search `q`; the active dimensions become
  chips. Priority and Estimate pick one
  `impact: *` or `effort: *` label, Labels are all-of, the rest any-of. Read
  the initial filters from the URL with `queryFromSearch(location.search)`
  and write them back with `pushQuery`.
- `DisplayMenu`, `DisplayRow` and `DisplaySelect`: the Display button and its
  panel of grouping, ordering and visibility rows (a `.switch` checkbox for a
  toggle). The board keeps its ordering in the URL (`sort`) and its card
  properties and empty columns in the browser.
- `Popover`: a menu or a group of controls under a trigger; it takes the
  focus, closes on Escape in the capture phase (a peek panel or a pane around
  it stays open) and on a click outside, and gives the focus back.
- `TaskDetails` with `client`, `id`, `onChanged`, `onBack`, `onExpand` and
  `variant` (`split` in the inbox, `full` for the page): it loads the task,
  holds the ETag and renders the issue: the article (the 48 px breadcrumb
  header with the issue menu: copy link, copy code, copy path, open on
  GitHub; the title, the body without a leading H1 that repeats the title,
  the activity) and the 340 px properties rail with its own toolbar (copy the
  link, copy the path, open on GitHub) and Priority and Estimate as menus
  that triage the labels. It shows "Saving…"
  and "Saved" under the property, the `412` reload offer that blocks both
  menus until then, the `409` and the `422` explanations. The layout follows
  its container: the rail sits on the right from 760 px, the article insets
  are 60 px from an 800 px article column and 24 px below.
- `IssuePage`: the full issue page over a page (add `page--issue` to the
  page's class), opened with `openTask(id)` from `lib/task.ts` and read with
  `useOpenTask()`; Back and Escape call `closeTask()`, and the page puts the
  focus back on the row or card that opened it.
- `Drawer`: the modal peek panel from the right, `wide` (960 px) or
  `narrow` (480 px), for the checkouts of the status page; it contains the focus, makes the rest of the page inert,
  locks the scroll, closes on Escape and gives the focus back.
- `Glyphs`: `StatusGlyph` for the five columns, `PriorityGlyph`,
  `EstimateGlyph`, `CheckoutGlyph` for the groups of the status list,
  `RepoAvatar`, `BrandMark` and `decorationOf`, the stable color of a name.
  `Chip`: `LabelChip`, `MetaChip`, `Priority`, `Estimate` and `TaskMeta`, the
  meta of a row or a card with `+N` for the labels it leaves out.
- `Loading` (a skeleton in the shape of the content), `Indexing`,
  `ProgressLine`, `ErrorState`, `Empty` with an optional action, and `Icon`.
- The sidebar's Repositories tree (`RepositoryTree`): every repository of the
  catalog by owner, `role="tree"` with arrow-key navigation, the expanded
  owners in localStorage, a lock from the catalog's `private`, the current
  repository from `repo` in the URL, kept in step through `QUERY_EVENT`, which
  `pushQuery` and `replaceSearch` dispatch.
- The sidebar's Reindex button in its action row: it POSTs `/api/v0/refresh`, polls the catalog
  until the generation changes and reloads the page, so a page need not watch
  the generation itself; `onStatus` puts a page's state under it.
- `TaskDetails` is keyed by the task id, so a new task is a new instance; a
  triage that completes for another task, or after the page went away, is
  dropped and `onChanged` is called for the open task only.

Tests use `mockApi()` from `src/api/mock.ts`: it answers the fixtures and
takes a `route` to override one request, `listStatus: 202` for the indexing
state, or your own `tasks` page. Keep page tests next to the page. The test
viewport is 1440 px wide (`vite.config.ts`); a narrow layout stubs
`matchMedia`.

## Design

[DESIGN.md](DESIGN.md) is the design system of the hub: the color, type,
radius and spacing tokens in its front matter are what `src/styles/tokens.css`
defines for the dark default and the light theme, and its prose says how the
shell and the components apply them, with the source of each measurement.
`base.css` implements the shared components (sidebar, top bar, filters,
menus, chips, glyphs, list rows, the issue page, the peek panel, states); a
page's css holds its own layout only. The app is a `100dvh` grid of the
220 px sidebar and the page; a page is a column of the 56 px top bar and the
content, which scrolls inside (`min-height: 0`), never the page. Icons are
inline Tabler paths in `Icon.tsx`; the status, priority and estimate glyphs
are drawn in `Glyphs.tsx`. The only dependency besides Preact is the Inter
typeface, `@fontsource-variable/inter` (OFL): `fonts.css` takes its latin,
latin-ext and cyrillic files, which Vite copies into `dist/assets`. When a
change needs a new token, change `DESIGN.md` first and check it with
`npx --yes @google/design.md lint DESIGN.md`.
