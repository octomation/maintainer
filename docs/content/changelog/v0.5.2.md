# v0.5.2 — As promised.

Maintainer v0.5.2 fixes fourteen places where a command or the hub did something other than what its guide says. Nothing changes in your configuration or state.

## Fetch

- `fetch config init` writes its template only to a `.toml` path. For another extension it stops with exit `2`, names the extension and writes nothing.
- `fetch state prune` removes only the records of the owners and profiles that `--owner` and `--profile` select. The records of other owners stay.
- Each verbosity level adds output during `--apply`: `-v` prints a line per action, `-vv` adds discovery, checks and the state save, and `-vvv` adds each Git operation with its time.
- An owner listed next to `*` in `include_owners` is discovered with your own repositories. An owner that GitHub does not know now stops the run with its name, as it does in a list without `*`.
- A new pin that GitHub answers with `404`, `403` or `451` becomes a conflict of its repository, with the reason in the plan. The rest of the plan goes on, and `--apply` exits `3`.

[See how fetch plans →](/fetch/)

## Status and contributions

- `status` works in a folder that you reached through a symlink: it scans the folder that the symlink names. A `--root` that names a symlink is still refused.
- The interactive `status` screen does not redraw while nothing changes, and it restores the terminal after an error.
- `github contribution lookup` prints its table on stdout, so `> pace.txt` keeps it. `suggest` keeps its table on stderr.
- `maintainer skill status` reports unknown compatibility for a binary built from a commit, instead of an incompatible skill.

## The hub

- An issue whose file no longer parses stays in the hub with its last good version, marked stale, when a triage change is refused. It updates once you repair the file.
- The group counts of the inbox follow every filter, the Status filter included.
- The repository tree of the sidebar appears once the catalog loads again after a failure.
- F, P, E and Escape work on the full issue page; F no longer opens a hidden filter menu.
- In a 390 px window the Filter menu stays inside the screen.
- `service.toml` refuses a `match.id` that is zero or negative, as its schema does.

[See the hub →](/service/)

## Known limitations

- `fetch` refuses a working directory reached through a symlink when the workspace root is that directory.
- The hub speaks plain HTTP. A program of another account that takes the port after the service stops sees the addresses that an open tab still requests. On a computer with other accounts, close the tabs of the hub before you stop the service.
- A change that keeps the total of a month, such as one contribution removed and another added, is not seen until the folder of fast repeat runs is deleted.
- An issue opened in the browser near midnight keeps the browser's date on the profile, and the contribution commands may put it a day off.
- The contribution commands count by calendar year, not by the profile's rolling twelve months.

**Upgrade:** with Homebrew, run `brew update` followed by `brew upgrade --formula octolab/tap/maintainer`, then `brew services restart octolab/tap/maintainer`. With the install script, pass the tag: `sh -s -- -b ~/.local/bin v0.5.2`. With Go, run `go install go.octolab.org/toolset/maintainer@v0.5.2`. For a manual installation, use a [v0.5.2 release archive](https://github.com/octomation/maintainer/releases/tag/v0.5.2). Run `maintainer version` to check the installed version. If you use the agent skill, [replace it](/agents/#keep-it-in-step) with the new binary’s copy.
