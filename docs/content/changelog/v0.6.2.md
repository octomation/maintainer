# v0.6.2 — Room to breathe.

Maintainer v0.6.2 stops one huge checkout from holding `status` and the hub, draws the contribution histogram in a terminal of ordinary width, and keeps `suggest` from spending the rest of your working day on its random offset. The install script now comes from `install.octolab.org`. The review skill writes its reports to `.github/reports/` and reads the security alerts that GitHub already has for your repository. Your configuration and state stay as they are.

## Status and the hub

- `git status` of one checkout has a bound of 10 seconds. A checkout with a very large tree no longer holds the run: on a workspace of 168 checkouts with one tree of 23 GB, `status` took 21 seconds instead of 96.
- Past the bound, the row keeps its repository, branch, divergence and push lock, and shows its uncommitted counts as `?`. It counts as uncommitted work and does not make `status` exit `1`. The hub shows the same row.
- In the JSON of `status`, `changed_files`, `untracked` and `conflicts` are `null` when they were not computed: past the bound, and in the rows of an error, a scan obstruction or an unresolved pin. Before, these rows gave `0`. Update a script that reads these fields as numbers.

[See what status shows →](/status/)

## Contributions

- `histogram` prints a header, the exact number of days for each count, and a bar of at most 40 characters. A year with 301 days of the same count fits one line of a terminal. The order of rows and `--with-zero` stay as they are.
- `suggest` scales its random offset to the contributions that the day still needs: the offset is at most the time left until now or the end of the working interval, divided by those contributions, and never more than an hour. With 50 contributions left and one hour available, it is under 72 seconds.

[Plan your contributions →](/contributions/)

## Install

- The install script is at `https://install.octolab.org/maintainer`. Each stable release renders it from its own archives, so it knows the platforms of the release and checks the archive against `checksums.txt`. The flags stay the same: `-b` for the folder and a tag to pin the version.

```sh
curl -sSf https://install.octolab.org/maintainer | sh -s -- -b ~/.local/bin v0.6.2
```

## Agent skills

- The review skill writes code and issue reports to `.github/reports/` and private security reports to `.agents/reports/`, and reads only these folders. Ask Git to ignore `.agents/reports/`.
- A security review also reads the Dependabot, code scanning and secret scanning alerts and the draft security advisories of the repository through `gh`. It checks whether your product ships the vulnerable code, and a dismissed alert counts as your decision while its reason holds.

## Known limitations

- A checkout past the bound still takes up to 20 seconds: one try with rename detection and one without.
- `fetch` cannot refresh a sparse checkout or a partial clone: `--apply` reports an error for it and exits `3`. Run `git fetch` in that checkout.
- The hub speaks plain HTTP. A program of another account that takes the port after the service stops sees the addresses that an open tab still requests. On a computer with other accounts, close the tabs of the hub before you stop the service.
- The catalog plugin and the binary carry the same skills only from v0.6.0 on: a plugin of an older release has the maintainer skill alone, and `skill status --exact` reports it.
- A change that keeps the total of a month, such as one contribution removed and another added, is not seen until the folder of fast repeat runs is deleted.
- An issue opened in the browser near midnight keeps the browser's date on the profile, and the contribution commands may put it a day off.
- The contribution commands count by calendar year, not by the profile's rolling twelve months.

**Upgrade:** with Homebrew, run `brew update` followed by `brew upgrade --formula octolab/tap/maintainer`, then `brew services restart octolab/tap/maintainer`. With the install script, pass the tag: `sh -s -- -b ~/.local/bin v0.6.2`. With Go, run `go install go.octolab.org/toolset/maintainer@v0.6.2`. For a manual installation, use a [v0.6.2 release archive](https://github.com/octomation/maintainer/releases/tag/v0.6.2). Run `maintainer version` to check the installed version. If you use the agent skill, [replace it](/agents/#keep-it-in-step) with the new binary’s copy.
