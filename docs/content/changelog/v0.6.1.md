# v0.6.1 — Within reach.

Maintainer v0.6.1 fixes twelve places where `fetch`, `status`, the contribution commands, the hub or the agent skills did less than their guides say. Your configuration and state stay as they are. The JSON of `status` now gives `null` for line counts that it did not compute.

## Fetch

- `fetch` recognises a sparse checkout and a partial clone of a tracked repository. When GitHub renames the repository, the plan moves the checkout and does not clone it a second time.
- A checkout that the scan cannot read, or a checkout inside a folder that it cannot read, is a conflict at its path with the reason. Its state record keeps the path, and `fetch` does not clone the repository again.
- A conflict that belongs to no repository names its path, not `/`.
- `fetch` works in a folder that you reached through a symlink, as `status` does: it scans the folder that the symlink names. A root that names a symlink is still refused.
- `fetch state prune` and `fetch state show` refuse a profile that your configuration does not have, with exit `2`, as `fetch` does. Before, a typo pruned nothing and exited `0`.

[See how fetch plans →](/fetch/)

## Status and contributions

- One slow checkout no longer holds the whole `status` run. Rename detection in a checkout stops after 10 seconds. The row keeps its branch, divergence and push lock, and shows its line counts as `+?/-?`.
- In the JSON of `status`, `added`, `deleted` and `binary` are `null` when they were not computed: after that limit, and in the rows of an error, a scan obstruction or an unresolved pin. Before, these rows gave `0`. Update a script that reads these fields as numbers.
- A month that took GitHub's calendar while it was still open is read again after it closes, so a review near midnight counts on its own day. Each such month in your cache is read again once after the upgrade.

## The hub

- In a window narrower than 600 px, every button, field, menu item and property of the hub offers a 44 × 44 px target. Links inside the text of an issue or a comment keep the size of their line.
- Closing the full issue page returns to the list without a second copy of it in the browser history, so Back leaves the list.
- Refresh during a collection runs one more collection, however often you press it.

[See the hub →](/service/)

## Agent skills

- `maintainer skill install` ends with a hint that names, for each agent, only the skills that it installed or found in place.
- The review skill asks you to ignore only `.agents/reviews/`, the folder of private reports, so the project skills in `.agents/skills/` stay in Git. It also states how it treats a named target larger than one pass, tests under `testdata/`, and the `Excluded` field.

## Known limitations

- `fetch` cannot refresh a sparse checkout or a partial clone: `--apply` reports an error for it and exits `3`. Run `git fetch` in that checkout.
- The catalog plugin and the binary carry the same skills only from v0.6.0 on: a plugin of an older release has the maintainer skill alone, and `skill status --exact` reports it.
- The hub speaks plain HTTP. A program of another account that takes the port after the service stops sees the addresses that an open tab still requests. On a computer with other accounts, close the tabs of the hub before you stop the service.
- A change that keeps the total of a month, such as one contribution removed and another added, is not seen until the folder of fast repeat runs is deleted.
- An issue opened in the browser near midnight keeps the browser's date on the profile, and the contribution commands may put it a day off.
- The contribution commands count by calendar year, not by the profile's rolling twelve months.

**Upgrade:** with Homebrew, run `brew update` followed by `brew upgrade --formula octolab/tap/maintainer`, then `brew services restart octolab/tap/maintainer`. With the install script, pass the tag: `sh -s -- -b ~/.local/bin v0.6.1`. With Go, run `go install go.octolab.org/toolset/maintainer@v0.6.1`. For a manual installation, use a [v0.6.1 release archive](https://github.com/octomation/maintainer/releases/tag/v0.6.1). Run `maintainer version` to check the installed version. If you use the agent skill, [replace it](/agents/#keep-it-in-step) with the new binary’s copy.
